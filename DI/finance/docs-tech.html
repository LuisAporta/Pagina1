Arquitectura y Programación

Análisis profundo del código y sistemas de datos

1. Base de Datos y Persistencia

El sistema utiliza **PostgreSQL** alojado en **Supabase** como motor principal. La integridad de los datos se mantiene mediante triggers a nivel de base de datos.

Esquema SQL (db_setup.sql)

-- Tabla de transacciones con integridad referencial
create table transactions (
  id uuid default uuid_generate_v4() primary key,
  user_id uuid references auth.users not null,
  amount numeric not null,
  type text check (type in ('income', 'expense')),
  date timestamp with time zone default now()
);

Lógica de Cálculo Automático: Se utiliza una función PL/SQL y un trigger (on_transaction_change) que recalcula el balance total del perfil cada vez que se inserta o borra una transacción. Esto garantiza que el "Líquido" sea siempre preciso sin sobrecargar el frontend.

2. Almacenamiento y Manejo de Archivos

La gestión de archivos se realiza mediante un sistema híbrido:

  • Frontend: FileReader de JavaScript para previsualización inmediata.
  • Backend: Supabase Storage API para persistencia en la nube.
  • Seguridad: Políticas RLS que impiden a un usuario ver los archivos de otro.

Función Clave

supabase.storage.from('receipts').upload(path, file)

Localizada en: transactions.html

3. Lógica Frontend y Analítica

Visualización Dinámica (Chart.js)

En dashboard.html, las gráficas se escalan dinámicamente según el rango de fechas de las transacciones. El sistema de "Cache Busting" implementado en v4.0 asegura que cualquier cambio en las gráficas se refleje de inmediato en el navegador del usuario.

Gestión de Sesiones y Estado

common.js actúa como el núcleo de la aplicación, inyectando la navegación en todas las páginas y controlando la autenticación mediante requireAuth(). Los datos de sesión se persisten de forma segura en localStorage.
