SYSTEM ARCHITECTURE

TECHNICAL DOCUMENTATION & LOGIC FLOW

1. Arquitectura Cliente-Servidor

Esta aplicación no es una página web estática simple. Utiliza una arquitectura donde el Frontend (Tu navegador) se comunica con un Backend (Servidor Node.js).

¿Por qué necesitamos un Backend?

Javascript ejecutándose en el navegador (Chrome/Edge) está "encerrado" por seguridad. No puede acceder directamente a la memoria RAM o CPU de tu ordenador. Para solucionar esto, usamos Node.js en el servidor, que sí tiene permisos de administrador para ejecutar comandos del sistema.

[NAVEGADOR]
(Pide datos: fetch('/api/ram'))
↓
[SERVIDOR NODE.JS]
(Ejecuta comando 'wmic' en Windows)
↓
[SISTEMA OPERATIVO]
(Retorna uso real de memoria)

2. Flujo de Datos

Start / Stop System

Al pulsar "INICIAR SISTEMA", el frontend envía una petición POST a /control/start. El servidor simula un retardo y cambia su variable interna de estado. Esto habilita los otros endpoints (RAM/CPU).

Gráficos en Tiempo Real

Utilizamos la librería Chart.js. Cada 5 segundos, el frontend pide /api/stats al servidor, que retorna un array con el historial simulado de uso de CPU y RAM.

3. Despliegue en Entornos Reales

En un entorno empresarial real, este dashboard no controlaría "tu PC", sino servidores remotos.

Uso de Máquinas Virtuales (VM)

Lo ideal es instalar este backend en diferentes Máquinas Virtuales (Linux/Windows Server). El Dashboard centralizaría la información de todas ellas mediante autenticación segura (SSH/Tokens).
